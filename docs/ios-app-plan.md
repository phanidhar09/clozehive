# Plan: ClozeHive Native iOS App — Full Parity (Phased)

## Context

ClozeHive today is a React (Vite) SPA + a FastAPI `api-gateway` backend. There is no native
mobile client. The goal is a **native SwiftUI iOS app that reaches full feature parity with the
web app**, built and shipped **in phases** so a usable App Store build lands early and the
heaviest surfaces (drag-and-drop builder, rich planners) don't gate the whole release.

Every web feature is driven by the same `api-gateway` REST/SSE/WebSocket API — there is no
web-only backend logic — so parity is a scope choice, not a technical blocker. The backend needs
**no changes for Phases 0–3**; the only required backend addition (Apple Sign In) is an App Store
prerequisite, not a feature gap.

Decisions confirmed with the user:
- **Approach:** Native SwiftUI (highest-fidelity iOS; not cross-platform).
- **Scope:** **Full parity, phased.** Destination = everything the web app does; delivered Tier 1 → 2 → 3.
- **Android:** Wanted "soon." Native SwiftUI shares **no UI** with Android — Android is a later
  Kotlin/Compose effort reusing only this same API contract. The endpoint/auth/model map defined
  here is the reusable cross-platform asset.
- **Excluded (for now):** Social **Groups** and **Avatar builder** — both are hidden behind a
  feature flag and incomplete on the web app itself. Deferred until the web versions ship. (Override
  if you want them in scope.)

## Architecture (shared across all phases)

- **Native SwiftUI, iOS 17+** (async/await, `@Observable`, `PhotosPicker`, modern `URLSession`).
  No heavy third-party deps.
- New top-level **`ios/`** directory in the monorepo (alongside `services/` + `frontend/`).
- Project generated by **XcodeGen** from a checked-in `project.yml` — reproducible, diff-friendly,
  no hand-edited `.pbxproj`. (`brew install xcodegen`.)
- **Tab-based navigation** mirroring the web `BottomNav`, growing per phase (see Navigation below).

### Directory layout (grows per phase; Core/App/DesignSystem are Phase 0)
```
ios/
  project.yml                      # XcodeGen spec
  Config/{Debug,Release}.xcconfig  # API_BASE_URL per config
  ClozeHive/
    App/            ClozeHiveApp, RootView (auth↔main), MainTabView (+ "More" menu)
    Core/
      Networking/   APIClient (actor; bearer + 401 single-flight refresh), Endpoint,
                    MultipartFormData, SSEClient (URLSession.bytes SSE parser),
                    WebSocketClient (ticket-authed realtime)
      Auth/         AuthStore (@Observable), TokenStore (Keychain)
      Config/       AppConfig (reads API_BASE_URL from Info.plist ← xcconfig)
    Models/         Codable mirrors of backend schemas (added per feature)
    Features/       one folder per feature area (view + view-model each)
    DesignSystem/   Theme.swift (colors/typography mirroring web Tailwind theme), shared components
  ClozeHiveTests/   model decoding, APIClient refresh, multipart, SSE parsing
```

### Cross-cutting mechanics (verified against the backend)
- **Base URL:** dev `http://localhost:8000`, all routes under `/api/v1`. Simulator reaches host `localhost` directly.
- **Auth:** `POST /auth/login` `{identifier,password}` → `{user, access_token}` in body + refresh
  token as an **HttpOnly cookie that `URLSession` captures/replays automatically**. Access token in
  **Keychain**; on `401` → single-flight `POST /auth/refresh` → replay; on failure → Login.
  Mirrors `frontend/src/lib/refreshAccessToken.ts`.
- **Image upload:** plain `multipart/form-data`; server does **HEIC→JPEG conversion**, EXIF strip,
  ≤10 MB. Response image URLs are absolute GCS HTTPS (prod) or root-relative `/uploads/...` (dev) —
  client must prefix the API origin for the relative case (mirror `resolveUploadUrl` in `api.ts`).
- **Chat streaming:** `POST /ai-chat/stream` is **SSE over POST** (`data: {json}\n\n` frames:
  `session`/`token`/`structured`/`done`/`error`) — use `URLSession.bytes(for:)`, NOT `EventSource`.
- **Realtime:** `POST /api/v1/ws/ticket` → connect `wss://host/api/v1/ws?ticket=…` (single-use ticket).
  Optional; used for live closet/notification updates. Deferred to Phase 3 polish.

### Backend API map by domain (route prefixes under `/api/v1`)
| Domain | Prefixes |
|---|---|
| Identity | `/auth`, `/profile` |

endpoint's schema at build time from the router + schema files (paths in the map above).

## Phased roadmap

### Phase 0 — Foundation (no user-facing features)
Scaffold + the spine every feature depends on.
- `project.yml`, xcconfig, `Info.plist` (`NSCameraUsageDescription`, `NSPhotoLibraryUsageDescription`,
  ATS localhost exception, `API_BASE_URL`).
- `AppConfig`, `APIClient`, `Endpoint`, `MultipartFormData`, `SSEClient`, `TokenStore`, `AuthStore`.
- `ClozeHiveApp` + `RootView` (auth↔main routing) + empty `MainTabView`.
- `DesignSystem/Theme` mirroring the web palette.
- **Auth UI:** Login, Signup, password reset. Google OAuth + Apple Sign In wired here (see follow-ups).
- **Onboarding:** style-profile quiz (`/onboarding` equivalent via `/profile`) — gates first login like web.
**Exit check:** app launches, user can sign up / log in / stay logged in across relaunch.

### Phase 1 — Camera-first core (first App Store build)
The phone's superpowers + the daily-use surfaces. Tabs: **Home · Closet · Add · Outfit · FANI**.
- **Closet** — grid list/filter (`GET /closet`), item detail, wear logging.
- **Add to closet (camera)** — `PhotosPicker`/camera → `POST /closet/analyze-preview` → edit AI tags
  → `POST /closet/confirm`. *(The star feature.)*
- **Dashboard** — greeting, outfit-of-the-day, daily FANI nudge (`GET /ai-chat/nudges/today`).
- **FANI stylist chat** — SSE streaming (`POST /ai-chat/stream`), sessions list/resume.
- **Shop with FANI** — snap a store item, FANI scores vs closet (`/shopping` + `/closet/analyze-preview`).
**Exit check:** a person can build their closet from their camera, get daily suggestions, chat, and
vet a purchase — a self-sufficient app. Ship to TestFlight/App Store.

### Phase 2 — Styling & shopping depth
The build-and-shop surfaces. Adds a **"Style"** section / tab.
- **Outfit builder** — native compose UI (tap-to-add + reorderable canvas rather than literal web
  drag-drop), FANI suggestions, save (`/outfits`, `/ai`). *Highest-effort surface — budget for it.*
- **Saved outfits** library (`/outfits`, `/outfits/history`).
- **Purchase gaps** — what to buy next (`/purchase-gaps`).
- **Closet match** — pick an item → FANI shopping suggestions (`/closet` + `/shopping`).
- **Profile & style settings** — edit style profile, fit prefs (`/profile`).
**Exit check:** full styling loop (assemble → save → shop the gaps) works natively.

### Phase 3 — Planning & insights
Planning-oriented surfaces + realtime polish. Adds a **"Plan"** section / tab.
- **Travel planner** — activity-aware packing/outfit plans, item/checklist editing (`/trips`, `/weather`).
- **Weekly planner** — assign outfits across the week (`/planner`).
- **Analytics** — cost-per-wear, wear tracking, utilization, forgotten gems (`/analytics` + wear data).
- **Realtime** — WebSocket live updates for closet/notifications (`/ws` ticket flow).
- **Legal/settings** — privacy/terms, logout-all, account export/delete (`/auth/me/export`, `DELETE /auth/me`).
**Exit check:** feature parity with the web app (minus deferred Groups/Avatar).

### Deferred — Groups & Avatar
Ship only after the web versions are completed and un-flagged. Same-API additions when ready.

## Verification (per phase)
Prereq: run the backend locally — `docker compose up api-gateway postgres redis` (gateway on
`localhost:8000`), plus a seeded test user.
1. **Once:** `brew install xcodegen` (done).
2. **Generate:** `cd ios && xcodegen generate`.
3. **Build & run:** iOS Simulator tooling — build the `ClozeHive` scheme, attach the live panel, launch.
4. **Per phase:** exercise that phase's flows against the local backend (auth persistence, camera →
   analyze/confirm hits both endpoints and the item appears; chat streams token-by-token; each new
   surface round-trips its endpoints). Screenshot each new tab/screen as proof.
5. **Tests:** `xcodebuild test` (or Simulator tooling) — model decoding, `APIClient` 401-refresh,
   multipart body, SSE frame parsing; add per-feature model tests as phases land.

## Prerequisites / follow-ups
- ⚠️ **Full Xcode must be installed** (only Command Line Tools present now) before anything builds or
  runs. `xcode-select --install` gives CLT; install **Xcode from the Mac App Store**, then
  `sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer`.
- **Apple Sign In** (Phase 0): App Store requires it once Google login is offered — needs a small
  backend addition (`/auth/apple/*` or extend `POST /auth/oauth/exchange`). Required **before**
  submission, not before local dev.
- Confirm the **prod gateway host** for the Release `API_BASE_URL`.
- **Effort note:** full parity is ~5–6× the Phase-1 MVP; cost is uneven — closet/dashboard/analytics/
  profile are cheap (lists/forms), while the **outfit builder** and **travel/weekly planners** are the
  large web pages (1,700+ lines) and the expensive ports. Phasing keeps them off the v1 critical path.
